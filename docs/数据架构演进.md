# 数据架构：本地原料 + Cloudflare D1（单一线上数据源）

> 2026-08-23 更新。项目已从「纯静态」彻底演进为「D1 单一数据源」架构：节目数据全部存 D1，前端全部走 API。

## 一、当前架构

```
本地（流水线产物，不部署、不提交音频/中间产物）
episodes/<id>/
├── meta.json          # 下载元数据
├── transcript.json    # ASR 转写（gitignore）
├── translation.json   # 逐句翻译（gitignore）
└── bilingual.json     # 对齐产物 → D1 灌库原料（提交）

线上（Cloudflare）
├── D1 数据库 cherina-pod-db
│   ├── episodes 表    # 元数据（完整字段：标题/简介/封面/节目封面/音频链接）
│   ├── pairs 表       # 逐句 {episode_id, idx, start, end, en, zh}
│   └── pairs_fts      # FTS5 全文索引（英文 unicode61 分词）
├── Worker（web/src/index.js）
│   ├── /api/episodes        # 发现页/频道页数据
│   ├── /api/episodes/:id    # 详情页数据（含逐句 pairs）
│   ├── /api/search          # 跨期全文搜索
│   └── 其余 → ASSETS 静态资产
├── 静态资产（web/public/）
│   ├── index.html           # 单页应用
│   ├── sitemap.xml          # SEO（migrate_to_d1.py 生成）
│   └── brand/ fonts/ robots.txt
└── 音频 → RustFS（自建 S3，前端拼 https://pod-audio.cherina.app/<id>.mp4）
```

**数据流是单向的：** `bilingual.json`（本地原料）→ `migrate_to_d1.py` → D1。线上不存在任何节目数据静态 JSON 副本。

## 二、为什么彻底进 D1

早期曾用「静态 JSON 直出 + D1 只管搜索」的混合方案，后改为彻底进 D1，理由：

1. **消除平行数据源**：混合方案下 D1 和静态 JSON 各存一份节目数据，靠脚本同步，容易漂移、维护成本高。
2. **静态 JSON 的"零成本直出"优势在当前规模下不成立**：21 期、约 1 万句，D1 查询延迟毫秒级；付费账户读写额度充裕。详情页走 `/api/episodes/:id` 一次往返即可拿全。
3. **统一数据层**：后续做筛选、分页、收藏、进度同步，都只需在 D1 上扩展，不再维护两套。

## 三、D1 实现细节

- **英文搜索**：FTS5 `MATCH`，unicode61 分词，按 `rank` 排序。
- **中文搜索**：FTS5 默认按空格分词，中文无空格，故用 `pairs.zh LIKE '%词%'` 兜底。规模到数万期再升级 trigram 分词器（SQLite 3.34+，D1 支持）。
- **FTS5 外部内容表**：`content='pairs'`，正文只存 `pairs` 一份，FTS 只存倒排索引；必须配 `AFTER INSERT/DELETE/UPDATE` 三个触发器同步，否则直接 INSERT 不会填充索引（实现时踩过的坑）。
- **迁移**：`scripts/migrate_to_d1.py` 读各期 `bilingual.json` + `podcast_meta.json`（category/level），生成分片 SQL（100 句/批，规避 D1 单语句 `SQLITE_TOOBIG` 限制）并生成 sitemap.xml；`deploy_web.sh` 发布前自动执行。
- **幂等**：0001_init.sql 是 DROP+CREATE，每次迁移全量重建，不会漂移。

## 四、触发条件与扩展路径

| 需求 | 现状 | 扩展 |
|---|---|---|
| 跨期搜句子 | ✅ 已上线 `/api/search` | — |
| 发现页/详情页 | ✅ 走 `/api/episodes` | — |
| 服务端筛选/分页 | 前端过滤（数据已全量返回） | `/api/episodes` 加 query 参数 |
| 生词收藏 / 进度云同步 | localStorage，仅本机 | 需用户体系，D1 表结构可扩展 |
| 中文全文检索升级 | LIKE 兜底 | 换 trigram 分词器，增量改 |

## 五、上线验证

```bash
# 发现页
curl -s "https://pod.cherina.app/api/episodes" | jq '.count'
# 详情页（含逐句）
curl -s "https://pod.cherina.app/api/episodes/497-biggest-mysteries-in-physics-antimatter-dark-e" | jq '.pairs | length'
# 英文 FTS
curl -s "https://pod.cherina.app/api/search?q=dark%20energy" | jq '.count'
# 中文 LIKE
curl -s "https://pod.cherina.app/api/search?q=物理" | jq '.count'
# 数据完整性
cd web && wrangler d1 execute cherina-pod-db --remote \
  --command="SELECT (SELECT COUNT(*) FROM episodes) e, (SELECT COUNT(*) FROM pairs) p, (SELECT COUNT(*) FROM pairs_fts) f;"
```
