## 0. 结论先行：商业模式与理想形态

### 0.1 商业模式：免费底座赚信任，钱全部赚在信任之上

**底座永久免费开源，用它换取信任与注意力；变现全部发生在信任之上，三扇门：**

| 门 | 卖什么 | 谁付钱 | 为什么付 | 开启前提 |
|---|---|---|---|---|
| **省事** | 托管订阅 / 买断支持包 | 想用但不愿部署、想跨设备同步的人 | 部署运维成本外化；对方是 CF 边际成本极低的托管 | 有活跃用户 |
| **坚持** | 付费社群 / 21–30 天精听营 | 学不下去的人 | 听力瓶颈是习惯不是工具；训练营=习惯养成器，双料 | 有 100 人（现在就能试） |
| **信任** | 捐赠 / 开源赞助位 / B 端 / 内容授权 | 想触达这群人的公司、机构、播客方 | 受众画像稀缺：开发者+语言学习者+隐私敏感 | 有案例 / 有数据 |

四条配套原则：

1. **免费版永不阉割**。阉割 = 断掉流量源头 = 付费无水可承。赞助/广告不进软件界面，只进"受众聚集处"（X 内容、仓库赞助位）。
2. **本地优先 = 免费版的完整性；同步 = 付费的省事**。学习数据（进度/连击/生词）是本地 JSON、一键导出；付费只买"跨设备、云备份、免运维"（Obsidian 模型）。**永不靠锁数据收费。**
3. **每一层注意力都要有对应的门**：X/开源流量 → fork 与托管；实例听众 → 训练营；实例运营者/老师 → B 端。没有门承接的注意力是浪费。
4. 收入排序（先到先得）：训练营 > 托管 > B 端/内容授权 > 赞助/捐赠。做的是**受众公司**，软件是沉淀受众的管道。

### 0.2 理想形态（3–5 年终局）

三层洋葱：

1. **内核（底座）**：数据契约 + 流水线 + 播放器模板。小、稳、语言无关、无服务依赖。参照系是 RSS 规范与 ffmpeg——是**方法的名字**，不是某个网站的名字。
2. **生态（实例）**：日语、西语、中→英……别人搭的实例到处跑；老师给自己的班搭一个、公司内训搭一个。搭一个实例 = 改 5 个环境变量 + 一次部署。
3. **主场（pod.cherina.app）**：生态里最大的公共广场——精听者每天的落脚点、训练营营地、品牌与信任的载体。

**"成了"的判断标准**（不靠直觉）：

- 出现**非我们搭建的、持续活跃的外部实例**；
- 有人自发写"我如何用 cherina-pod 学 ×× 语"的教程；
- 说"把播客做成精听"时，用的是这个底座（像说"用 Markdown 写"）。

## 1. 用户与核心循环

### 1.1 谁在用

| 用户 | 场景 | 他们的判断标准 |
|---|---|---|
| **自学者（主力）** | 通勤/睡前的 3–10 分钟，用真正想听的内容练精听 | "明天还会回来" |
| **老师 / 教练（放大器）** | 给班级/社群布置精听作业 | 省事、能看学生进度 |
| **自部署玩家（种子）** | 技术型；fork → 建实例 → 写教程 | 一条命令跑通、契约干净 |

### 1.2 核心循环（所有需求都必须服务它）

```
打开 → 继续上次那句 → 听 →（没懂）单句循环/看原文 → 懂了 → 下一句
     → 收尾（"今天 8 分钟 · 42 句 · 连续 7 天"）→ 明天再来
```

## 2. 三种形态与边界

| 形态 | 是什么 | 明确不做 |
|---|---|---|
| **底座**（`scripts/` + web 模板） | 引擎与契约：fetch → transcribe → translate → align → D1/静态 → 播放器 | 不分发第三方内容、不要求账号、不替用户搭服务 |
| **skill**（`skills/`） | 编排入口：一句话把一期内容变成精听课；agent 世界的触点 | 不持有独立数据与状态 |
| **实例**（pod.cherina.app） | 公共广场 + 商业化主场 | 公共区只放授权/CC/自制内容；用户私有处理默认私密、不公开、不索引 |

## 3. 需求

### 3.1 P0 · 核心循环无缝化（M1）

现状已有：逐句对齐播放、双语/原文/译文三模式、单句循环、倍速、全文搜索、本地进度 + "继续听"、深浅色。

缺口与需求：

- **R1 收尾反馈**：一次精听结束（主动退出或听完整期）给结算页：本次句数 / 时长 / "连续 N 天"。纯本地，无需账号。
- **R2 连击（streak）**：本地记录连续精听天数，首页可见。
- **R3 盲听按钮**：一键"先藏文本听 2 遍"——精听的本义是先耳朵后眼睛，把它做成一个按钮而不是教程里的规矩。
- **R4 A-B 区间循环**：长句内部反复磨。
- **R5 生词本（本地）**：一键收藏句子/词；导出 Anki CSV / JSON。
- **R6 移动端最低线**：手机上能听、能看、能循环；触控尺寸合格。

验收线：陌生人从打开首页到完成一次 3 分钟精听 ≤ 2 次点击（"继续听"直接开播为 1 次）。

### 3.2 P1 · 内容进入更顺

- **R7 本地音频导入**：`run_pipeline.py` 支持用户自己的音频文件（录音/自购素材），不限于 RSS。
- **R8 订阅与批量**：jobs 列表批量跑（已有）+ 定时更新文档；实例侧固定发布节奏。
- 待决：YouTube 等平台音源**不内置**（ToS 风险），只走 RSS 与本地文件两条合规通道。

### 3.3 P2 · 生态可见（M2）

- **R9 ASR 适配器示例**：`transcript.json` 契约已定，配 1–2 个开源 ASR 示例实现（mlx-whisper / whisper.cpp），换 ASR 不动下游链路。
- **R10 一键部署**：Deploy to Cloudflare 按钮 + 五步文档。
- **R11 多实例脚手架**：fork 后改 env 即换语言对/站点名/音源；写《做一个你自己的实例》教程。
- **R12 外部实例试验**：促成第一个**非我们**搭出的、真实在用的实例。

### 3.4 P3 · 商业门（M3+，产品所需的最小支撑）

- **R13 账号与同步**：闭源、独立服务，不碰底座代码；注册只承载学习数据（JSON 双向导入导出）；无账号功能无损。
- **R14 托管私享处理**：提交自己的 RSS/音频 → 云端生成 → **默认私密**。这是"省事"门的主力功能，也是实例侧唯一合理的云端处理形态（不公开、不索引、不分享）。
- **R15 训练营支撑（故意做轻）**：首期用微信群/Notion 手动运营；产品只提供分享卡片（成绩/连击）与班级收录码。**不做过早的班级系统。**

### 3.5 非目标（红线）

- 底座不内置、不抓取、不公开分发任何第三方版权内容；公共实例只收录授权/CC/自有内容。
- 不做强制注册、不做 DRM、不做信息流社交、不做题库/应试课。
- 付费永不阉割免费核心功能与数据可携带性。
- 一年内不做原生 App（PWA 优先）。

## 4. 指标

- **北极星：每周完成 ≥3 次、每次 ≥3 分钟精听的人数（WAU 3×3）。**
- 过程：继续听使用率 / 单期完成率 / 连续 7 天比例 / fork·star 数 / skill 安装量 / 播放深入度。
- 商业：训练营首期报名（目标 30–50 人）/ 托管版转化率（付费占活跃）。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 版权 | 结构性解决：内容不进底座；公共区只放授权/CC；私有处理默认私密（见 3.5） |
| 大厂/竞品跟进 | 品类被验证是好事；护城河 = 开放 + 数据主权 + 社区信任，抄不走 |
| "三分钟习惯"形不成 | R1/R2 以指标驱动迭代；训练营直接买习惯 |
| ASR/翻译成本 | 保留本地 ASR 路线（R9）；托管侧做配额 |
| bus factor = 1 | 文档/skill/CI 已起步；M2 目标引入外部贡献者 |
