# cherina-pod 技术方案

> 英文播客学习网页：本地转写 + 双语对照，线上只做展示。

## 1. 产品定位

输入英文播客（音频外链即可，不自己上传/存储音频），完成：

1. 语音转文字（英文，**保留词级时间戳**）
2. 逐句翻译成中文（DeepSeek V4 Flash，信达雅风格）
3. 双语逐句对照展示（一句英文 + 一句中文交错）

**形态**：重本地、轻线上。转写和翻译全部在本地完成；线上（Cloudflare Worker）只部署一个纯展示网页，读取本地生成的双语 JSON。

**第一版原则**：不追求全自动、不追求完善，先把闭环跑通。

## 2. 总体架构

## 3. 数据获取（播客 RSS 生态）

### 3.1 核心机制：RSS

每个播客都有一个 RSS 订阅地址，包含全部信息：

| 数据 | RSS 位置 |
|---|---|
| 音频文件 | 每集 `<enclosure url="...mp3">` |
| 封面 | `<itunes:image>` |
| 作者 / 节目名 | `<itunes:author>` / `<title>` |
| 单集列表 | 每集一个 `<item>`（标题、描述、时长、发布日期） |

### 3.2 获取 RSS 的入口

1. **iTunes Search API**（免费、无需 Key）：
   ```
   https://itunes.apple.com/search?term=播客名&media=podcast&entity=podcast
   ```
   返回：封面图、作者、`feedUrl`（RSS 地址）。
   单集查询：`https://itunes.apple.com/lookup?id=<podcastId>&entity=podcastEpisode&limit=200`
   限制：约每分钟 20 次调用；Lookup 只返回最近约 200 集，历史全集需解析 RSS。

2. **Podcast Index API**（免费注册拿 Key）：更全的开放索引，备用。

3. **手动粘贴**：直接粘贴 RSS 链接或音频直链。

### 3.3 浏览器插件（第二版，不在第一版范围）

在 Apple Podcasts 等页面加"加入队列"按钮，把任务写进本地文件，本地脚本轮询处理。等第一版跑顺了再上。

## 4. 本地流水线（核心）

做成项目内 skill，包含以下环节：

### 4.1 播客获取
- 输入播客名 → iTunes API 搜索 → 拿到 RSS → 解析单集列表
- 展示单集（标题、日期、时长）→ 用户选一集 → 下载音频到本地

### 4.2 转写（阿里云 Paraformer）
- 复用 creator-forge 的 `asr_paraformer.py` 思路（阿里云百炼 DashScope）
- 输出**词级时间戳**的英文文本，是逐句对齐的基础
- Key：`DASHSCOPE_API_KEY`

### 4.3 翻译（DeepSeek V4 Flash）
- 调 OpenAI 兼容格式 `/chat/completions`
- **双供应商负载均衡**：
  - `ollama-cloud`：`https://ollama.com/v1`（key：`OLLAMA_API_KEY`）
  - `opencode-go`：`https://opencode.ai/zen/go/v1`（key：`OPENCODE_API_KEY`）
- 轮询/随机切换，失败自动切另一家
- 按句翻译，输出 JSON，句句对应原时间戳

### 4.4 对齐与产出
- 英文句 + 中文句 + 时间戳 + 节目元数据 合并 → `bilingual.json`
- 这是线上网页的唯一数据源

## 5. 翻译 Prompt 设计（借鉴 baoyu-translate 信达雅方法论）

### 5.1 风格设定
- 基础风格：`elegant`（信达雅，文学性、措辞考究）
- 因是口语播客：混入 `conversational`（自然口语感）——译文像母语者说话，不僵硬

### 5.2 核心翻译原则
1. **准确优先**：事实、数字、逻辑与原文完全一致
2. **自然流畅**：按中文母语者习惯重组句子，长句拆短句，不逐字硬翻
3. **术语一致**：人名/专有名词保持统一译法，首次出现括注原文（如 OpenAI（开放人工智能））
4. **信达雅分层**：
   - 达（通顺）：不"翻译腔"
   - 雅（文采）：保留播客原语气（幽默/严肃/口语）
   - 信（准确）：不增删、不改义
5. **翻译腔排查**：避免"因此/然而/此外"堆砌、避免"被/由/受到"滥用、避免名词堆叠

### 5.3 输出格式
逐句返回 JSON，与转写时间戳一一对应：

```json
{
  "en": "原英文句",
  "zh": "中文翻译",
  "start": 12.3,
  "end": 15.8
}
```

### 5.4 参考来源
- JimLiu/baoyu-skills 的 `baoyu-translate`（MIT，参考其 prompt 方法论）：
  https://github.com/JimLiu/baoyu-skills

## 6. 线上展示网页（Cloudflare Worker）

- 极简单页：加载 `bilingual.json`
- 展示：封面 + 作者 + 节目名 + 单集标题 + 双语逐句对照
- 可选：顶部音频播放器（外链），点击某句跳转对应时间点
- Worker 直接 serve 静态文件，免费额度足够个人用

## 7. GitHub 推送流程

1. 项目初始化 + 首次 commit + push 到 `github.com/realchendahuang/cherina-pod`
2. 每处理完一期播客 → 生成新的 `bilingual.json`（或每期一个目录）→ push
3. Cloudflare Worker 读取 / 或 push 时自动更新 → 线上看到新一期

## 8. Key 管理

本地 `.env`（gitignore，**不进仓库**）：

```
DASHSCOPE_API_KEY=   # 阿里云百炼，转写
OLLAMA_API_KEY=      # ollama-cloud，翻译
OPENCODE_API_KEY=    # opencode-go，翻译
```

从 creator-forge 拷贝：`DASHSCOPE_API_KEY` 在其 `.env` 中；`OLLAMA_API_KEY` / `OPENCODE_API_KEY` 在 `~/.local/share/opencode/auth.json`。
