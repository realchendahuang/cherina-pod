# 音频存储与格式方案（自建 RustFS + Cloudflare 缓存）

> 2026-08-12 定稿。解决两件事：① 网页播放的音频与转写时间戳不同源（RSS 外链动态插广告导致音文漂移）；② 音频不该进 Cloudflare 静态资产（25MiB 单文件上限 + 占免费额度）。

## 决策

### 音频格式：AAC-LC 64kbps 单声道，MP4 容器，文件扩展名 `.mp4`

- 语音场景 64k mono AAC-LC 听感 ≈ 96–128k MP3，体积直接砍半（存量 11 期 490MB → 约 243MB）。
- AAC-LC 全浏览器原生支持（含任意年代 Safari）。Opus 更省但 Safari 18.4 才支持且实测不稳，否决；HE-AAC 需要 libfdk_aac（Homebrew ffmpeg 不带），否决。
- **扩展名用 `.mp4` 而非 `.m4a`**：Cloudflare 默认缓存扩展名列表含 mp4 不含 m4a，这样无需任何 Cache Rule 即可被边缘缓存。上传时显式设置 `Content-Type: audio/mp4`，浏览器 `<audio>` 正常解码。
- 压缩命令：`ffmpeg -i in.mp3 -ac 1 -c:a aac -b:a 64k out.mp4`（流水线已内置，见 `fetch_podcast.py`）。

### 存储与分发：ht 服务器 RustFS（源站）→ Cloudflare Tunnel → 边缘缓存

```
浏览器 → https://pod-audio.cherina.app/<episode_id>.mp4
         （CF 边缘缓存，.mp4 默认缓存，命中率≈100%，回源≈0）
              │ miss
              ↓ cloudflared tunnel cherina-db-ops（ht 出站，无需公网开端口/源站证书）
         ht nginx :9202  路径重写 /id.mp4 → /cherina-pod-audio/id.mp4
              ↓
         ht: cherina-rustfs (docker, S3 :9200 绑 tailscale+localhost, console :9201)
```

- **域名用一级子域 `pod-audio.cherina.app`**（不要用 `audio.pod.cherina.app`）：后者在部分网络/代理下 TLS 握手会直接被掐断；前者由 `*.cherina.app` Universal SSL 覆盖，本机与浏览器实测可通。
- **成本**：存储 0（自有盘）、流量 0（CF 扛）、不占 CF 免费存储额度。Hetzner 自带 20TB/月流量兜底回源。
- **可用性**：单源站宕机只影响未缓存的新内容，已缓存的期照常播；播放器保留 RSS 外链作为最终兜底。
- **RustFS 注意**：只用单节点（分布式模式还是 beta）；数据目录须 `chown 10001:10001`。
- 上传通道：RustFS S3 API 绑定 tailscale IP（`http://<TAILNET_IP>:9200`），本地流水线经 tailnet 直传，不经过 CF。
- Bucket `cherina-pod-audio` 设匿名只读策略（public read），对象键 `<episode_id>.mp4`。

### 流水线改动

- `fetch_podcast.py`：下载原始音频后自动压缩为 `.mp4`（AAC 64k mono），`meta.json` 的 `audio_path` 指向压缩产物；默认删除原始文件（`--keep-original` 可保留）。
- `transcribe.py`：转写压缩后的文件（与线上播放同源，时间轴锁死）；上传 OSS 时用真实扩展名与 Content-Type。
- `sync_web.py`：不再往 `web/public` 拷音频，改为把每期压缩音频 S3 上传到 RustFS（幂等，已存在跳过）。
- 播放器（`web/public/index.html`）：音源优先级 **自建源 `https://pod-audio.cherina.app/<id>.mp4`** → 报错回退 **RSS 外链**（HTTPS 才可用，http 外链直接跳过）。本地静态音频彻底移除。
- `bilingual.json` 结构不变；播放器按 episode id 拼自建源地址。

### 存量迁移

11 期就地重压（复用已有 transcript，AAC 编码引入的时间偏移 <50ms，句级同步无感知；**新期一律先压后转写**），上传后清理 `web/public/episodes/*/audio/`。

## 运维速查

```bash
# ht 上启停
ssh ht 'cd /srv/cherina_rustfs && docker compose up -d'   # 启
ssh ht 'cd /srv/cherina_rustfs && docker compose logs -f' # 日志
# tunnel（复用 cherina-db-ops）
ssh ht 'systemctl status cherina-db-ops-cloudflared'
ssh ht 'docker logs cherina-db-ops-cloudflared --tail 50'
# nginx 重写层
ssh ht 'curl -sI http://127.0.0.1:9202/advice-line-strategy-sessions.mp4 | head'
# 本地上传/同步
python3 scripts/sync_web.py
# 控制台（tailnet 内）
open http://<TAILNET_IP>:9201
```

## 一次性手工步骤（已完成的存档）

1. RustFS 单节点 + bucket `cherina-pod-audio` 匿名只读；存量 11 期上传为 `<id>.mp4`。
2. ht nginx：`/etc/nginx/conf.d/cherina-pod-audio.conf` 监听 `127.0.0.1:9202`，rewrite 到 path-style S3。
3. 复用 tunnel `cherina-db-ops`（id `<TUNNEL_ID>`）remote config：`pod-audio.cherina.app` → `http://127.0.0.1:9202`。
4. DNS CNAME：`pod-audio.cherina.app` → `<TUNNEL_ID>.cfargotunnel.com`（橙色云代理）。
5. `wrangler deploy` 网页播放器优先自建源。
