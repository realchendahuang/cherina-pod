# 音频存储与格式方案（自建 RustFS + Cloudflare 缓存）

> 2026-08-12 定稿。解决两件事：① 网页播放的音频与转写时间戳不同源（RSS 外链动态插广告导致音文漂移）；② 音频不该进 Cloudflare 静态资产（25MiB 单文件上限 + 占免费额度）。

## 决策

### 音频格式：AAC-LC 64kbps 单声道，MP4 容器，文件扩展名 `.mp4`

- 语音场景 64k mono AAC-LC 听感 ≈ 96–128k MP3，体积直接砍半（存量 11 期 490MB → 约 243MB）。
- AAC-LC 全浏览器原生支持（含任意年代 Safari）。Opus 更省但 Safari 18.4 才支持且实测不稳，否决；HE-AAC 需要 libfdk_aac（Homebrew ffmpeg 不带），否决。
- **扩展名用 `.mp4` 而非 `.m4a`**：Cloudflare 默认缓存扩展名列表含 mp4 不含 m4a，这样无需任何 Cache Rule 即可被边缘缓存。上传时显式设置 `Content-Type: audio/mp4`，浏览器 `<audio>` 正常解码。
- 压缩命令：`ffmpeg -i in.mp3 -ac 1 -c:a aac -b:a 64k out.mp4`（流水线已内置，见 `fetch_podcast.py`）。

### 存储与分发：自建 S3 源站 → Cloudflare Tunnel → 边缘缓存

> 下面是**通用形态**。维护者自用实例的服务器别名、目录、tunnel 名等运维细节已从本仓库移除（见 `private/`，不出库）；你要自建时按这里的形态套自己的参数即可。

```
浏览器 → https://<你的音频子域>/<episode_id>.mp4
         （CF 边缘缓存，.mp4 默认缓存，命中率≈100%，回源≈0）
              │ miss
              ↓ cloudflared tunnel（源站出站，无需公网开端口 / 源站证书）
         nginx :9202  路径重写 /id.mp4 → /<你的 bucket>/id.mp4
              ↓
         RustFS / MinIO（docker，S3 API 绑内网 + localhost，控制台 :9201）
```

- **域名用一级子域**（如 `pod-audio.example.com`，不要用 `audio.pod.example.com`）：后者在部分网络/代理下 TLS 握手会直接被掐断；一级子域由 `*.example.com` Universal SSL 覆盖，实测更稳。
- **成本**：存储 0（自有盘）、流量 0（CF 扛）、不占 CF 免费存储额度。任何有月流量配额的 VPS 都够用（Hetzner 自带 20TB/月）。
- **可用性**：单源站宕机只影响未缓存的新内容，已缓存的期照常播；播放器保留 RSS 外链作为最终兜底。
- **RustFS 注意**：只用单节点（分布式模式还是 beta）；数据目录须 `chown 10001:10001`。
- 上传通道：S3 API 绑内网地址（`http://<私有地址>:9200`），本地流水线直传，不经过 CF。
- Bucket 设匿名只读策略（public read），对象键 `<episode_id>.mp4`。

### 流水线改动

- `fetch_podcast.py`：下载原始音频后自动压缩为 `.mp4`（AAC 64k mono），`meta.json` 的 `audio_path` 指向压缩产物；默认删除原始文件（`--keep-original` 可保留）。
- `transcribe.py`：转写压缩后的文件（与线上播放同源，时间轴锁死）；上传 OSS 时用真实扩展名与 Content-Type。
- `sync_web.py`：不再往 `web/public` 拷音频，改为把每期压缩音频 S3 上传到 RustFS（幂等，已存在跳过）。
- 播放器（`web/src/app.ts`）：音源优先级 **自建源**（构建期注入的 `AUDIO_CDN` + `<id>.mp4`）→ 报错回退 **RSS 外链**（HTTPS 才可用，http 外链直接跳过）。未配置 `AUDIO_CDN` 时直接用 RSS 外链。本地静态音频彻底移除。
- `bilingual.json` 结构不变；播放器按 episode id 拼自建源地址。

### 存量迁移

11 期就地重压（复用已有 transcript，AAC 编码引入的时间偏移 <50ms，句级同步无感知；**新期一律先压后转写**），上传后清理 `web/public/episodes/*/audio/`。

## 运维速查（通用）

```bash
# 源站启停
ssh <你的服务器> 'cd /srv/<你的目录> && docker compose up -d'   # 启
ssh <你的服务器> 'cd /srv/<你的目录> && docker compose logs -f' # 日志
# cloudflared
ssh <你的服务器> 'systemctl status <你的 tunnel 服务名>'
ssh <你的服务器> 'docker logs <你的 tunnel 服务名> --tail 50'
# nginx 重写层自检
ssh <你的服务器> 'curl -sI http://127.0.0.1:9202/<episode_id>.mp4 | head'
# 本地上传/同步
python3 scripts/sync_web.py
# 控制台（仅内网可达）
open http://<私有地址>:9201
```

## 一次性手工步骤

1. RustFS 单节点（或任意 S3 兼容存储）+ bucket 匿名只读；存量音频上传为 `<id>.mp4`。
2. nginx：写一个 conf 监听 `127.0.0.1:9202`，rewrite 到 path-style S3（例：`/^([^\/]+)\.mp4$/ /<bucket>/$1.mp4 break;`），不暴露 bucket 名。
3. 建（或复用）一个 cloudflared tunnel，remote config：`<你的音频子域>` → `http://127.0.0.1:9202`。
4. DNS CNAME：`<你的音频子域>` → `<TUNNEL_ID>.cfargotunnel.com`（橙色云代理）。
5. 构建前端时设 `AUDIO_CDN=https://<你的音频子域>/`；不设则播放器直接走 RSS 外链。
6. `wrangler deploy` 上线网页。
